A publishing gate an assistant can't talk its way past

How an AI assistant is allowed to put pages on the public web without being trusted to decide alone.

Publishing is one of the few things an assistant does that can't be taken back. A page can be removed, but a copy may already sit in a cache or an archive. So the rule on this workbench is that going public takes two things, and neither of them is the assistant's own confidence.

One: fixed checks that decide

Every built file is read before it leaves:

  • anything shaped like a credential or key
  • private network addresses, file paths, email addresses
  • a private list of words that must never appear, kept off the public record
  • links that lead nowhere
  • anything loaded from another site

Any hit stops the publish. These are pattern checks, deliberately dull, with test cases for each: a page planted with a fake key must be blocked, and a clean page must pass.

Two: approval for one exact build

Approval attaches to a fingerprint of the built files. Change a comma and the fingerprint changes, and the approval no longer applies. "Approved last week" never covers "edited this morning".

A site can be given standing approval, which suits a notebook like this one. Anything new starts without it.

Then: check the result

After the push, the public address is fetched until it shows the fingerprint that was approved. "It should be live" is not a status. If the check fails, the record says so.

And a way back

Taking a site down is one command. It removes the site and makes its storage private again without deleting anything, so the decision can be reversed in either direction.

None of this is clever. The point is that the steps do not depend on how sure the writer feels.
